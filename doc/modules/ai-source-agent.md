# AI 书源工程 Agent

## 目标

AI 书源工程 Agent 用于两类任务：

1. 根据小说网站 URL 生成可供 LegadoHOS 执行的搜索、发现、详情、目录和正文规则。
2. 对已经失效的书源做分组诊断，只修复失败规则，并保留可回滚版本。

Agent 不把模型返回的 JSON 直接视为成功结果。每个规则阶段都必须通过
`SourceExecutor` 的真实网络请求和解析，再由 `SourceChecker` 完成全链路验收。

## 执行流程

```text
首页取证
  → 搜索入口/表单推导
  → 搜索规则生成与执行
  → 发现规则生成与执行（可选）
  → 详情规则生成与执行
  → 目录规则生成与执行
  → 正文抽样生成与执行
  → SourceChecker 全链路校验
  → 生成新书源 / 应用修复版本
```

每个核心阶段最多进行两轮。第一轮可以验证旧规则或模型候选；失败信息会进入
下一轮提示。新书源只有发现能力是可选项，搜索、详情、目录、正文任一阶段失败
都不会产生可应用结果。

## 页面取证与浏览器接管

- 优先使用普通 HTTP，保留实际 DOM 结构供模型生成选择器。
- WAF 探针、SPA 空壳、登录门禁或书源显式 `webView` 配置会切换到隐藏 WebView。
- 仍需人工操作时弹出交互式 WebView，用户完成登录或人机验证后继续。
- 现有书源 JS 调用验证码能力时，复用 `JsExpressionEvaluator` 的验证码对话框。
- 图片验证码页优先复用已有的 `java.getVerificationCode` + `java.ajax`/`java.post`
  提交流程；若验证码由站点页面脚本处理，则在交互式 WebView 中让用户完成，并在
  真实书籍结果出现后继续取证。两种方式都未得到真实结果时，Agent 必须拒绝该搜索规则。
- 发现页封面属于可选字段；如果模型返回 `background-image`/`@style` 等非法规则，
  Agent 会依据页面证据修正为 `img@src`/懒加载属性；页面没有图片证据时才置空，
  不能让非法 CSS 规则进入最终书源。
- POST 搜索会保留 method/body；浏览器目前只重放 GET 导航。

详情、目录和正文共用 `SourceExecutor.fetchWithOpts` 的浏览器兜底，因此通过
Agent 生成或修复后的规则，在普通阅读链路中也具备相同能力。

## 安全边界

- 只接受公网 HTTP(S) URL，拒绝本地、内网和非网络协议。
- 页面内容按不可信输入处理；模型系统提示禁止执行网页中的指令。
- 发送给模型前移除脚本、样式、注释、密码、Token、CSRF、Authorization 等值。
- 模型每个阶段只能写入该阶段的白名单字符串字段。
- 新生成书源默认停用，用户进入编辑页确认后保存。

## 修复与回滚

规则调试页把 `SourceChecker.invalidGroups` 传给 Agent。Agent 从原书源的浅副本
开始，保留未知扩展字段和用户管理字段，并优先验证未标记失效的旧规则。

应用修复时，以下操作在同一数据库事务中完成：

1. 向 `source_revisions` 写入修复前后 JSON、原因和变化字段。
2. 更新原书源，保留 ID、名称、URL、分组、启用状态、排序和权重。

规则调试页的“回滚最近修复”会恢复最近一个仍处于 applied 状态的版本，并将该
版本标记为已回滚；可继续逐次回滚更早的修复。

## 当前边界

- 标准 HTML GET/POST 搜索表单、静态页面、常见 SPA/WAF 和人工登录流程已覆盖。
- 依赖复杂签名、专用加密、付费授权或站点私有 App API 的书源，仍可能需要人工
  编写 JS，或先扩展 QuickJS/网络桥接能力。
- 图片验证码支持已有书源的验证码 JS 提交流程和站点页面脚本的交互 WebView；
  对没有可执行提交规则、也不能由用户在页面内完成的验证码，仍不会自动猜测提交接口。
- 实际成功率应按站点类型分桶统计，至少记录阶段失败、WebView 接管、模型重试和
  最终全链路通过率，再据此扩充确定性适配器。
